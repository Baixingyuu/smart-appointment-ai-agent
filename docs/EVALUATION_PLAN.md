# 评测体系完善计划（2026-09-18 修订）

> 本文档是 `docs/HANDOVER.md` §8「建议的下一步」的修订版，取代其优先级排序。
> 修订依据是三条共识：
> 1. **金标可由人工标注**——不再受"必须规则推导/自动生成"限制；
> 2. **一切围绕业务场景**——不为跑通或方便妥协，短期做不到的显式列入后续计划；
> 3. **评测不为可复现而过度追求确定性**——可引入 LLM judge，靠多次运行与元验证保证可靠性。

## 一、业务真实性审查结论（对现有体系的三处妥协）

| # | 妥协点 | 后果 | 处置 |
|---|---|---|---|
| C1 | 指派评测直接给出 `requiredSkillIds`，跳过「工单文本 → 技能需求」抽取环节 | 派单准确率的上游（技能抽取）零覆盖，抽取错了派单再准也错 | 补「技能抽取」轴（短期 #6） |
| C2 | 检索门控阈值（词项≥2 且原始 BM25 分≥3.0）在 32 chunk 语料上校准，原始分随语料规模漂移 | 「假命中率 10%」对生产规模知识库不成立 | 敏感性实验，列后续计划 #10 |
| C3 | 轨迹数据集 16 条，消息形态几乎只有「单消息」「消息+确认」 | 真实高频形态（多轮信息补全后建单）零覆盖，恰是 live 失败集中区 | 人工编写扩容（短期 #8） |

另有两点**边界声明**（非妥协，但要显式记录）：
- 意图/检索数据集口语化设计良好，但**分布是构造的**，未经真实流量校准；
- BM25 优于小模型稠密向量是推断而非实测，需 embedding 对照实验验证（后续计划 #11）。

## 三、LLM-judge 可靠性协议

**分界原则**：工具序列、轮次、越界、token 等离散信号保持确定性断言（精确比对不是过度设计，这些信号本身就是离散的）；judge 只补确定性够不到的两层——

1. **回答质量**：faithfulness（回答被检索证据支撑）、答案相关性、是否实际解决问题；
2. **语义级终态**：如 tj-005/006 类口径弹性问题。

**协议**：

| 机制 | 做法 | 理由 |
|---|---|---|
| 多次运行 | N=3–5，报告均值±标准差，样本级记录**翻转率** | 翻转率比均值更早暴露噪声，不稳定样本本身指向问题边界 |
| 多数投票 | N 次判定取众数为样本终判 | 单次 judge 错误不进结论 |
| 模型解耦 | judge 与被测模型不同源 | 避免同源自评偏差 |
| 元验证 | 人工标 30–50 条，一致率 Cohen's κ ≥ 0.7 才启用 | judge 可信的前提 |
| prompt 版本化 | judge prompt 进版本控制，报告记录 hash | 跨版本对比时能发现判据变了 |
| 隔离报告 | judge 指标单独成轴，不混入确定性 PassRate | 两种口径数字不可加 |

成本：judge 单次 1–2k token，16 用例 × 5 次 < 15 万 token，可行。

## 四、指标口径升级

- 指派报告金标增加 `gold_source` 字段：`"derived"`（规则推导）/ `"human"`（人工标注），为口径切换预留，避免新旧数字混读。
- 长期目标：规则-人工一致率 + 派单器对规则实现率（现有 100%）共同构成指派轴的完整表述——
  **「派单器 100% 实现了规则，规则本身 X% 符合人的判断」**。
