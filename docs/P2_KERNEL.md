## 数字 ①：层 1 服务抽取（金标 = 人工写的 `serviceTop1`，45 条）

查询文本钉死为 `Ticket.text = 标题 + "。" + 描述`。

| 指标 | 值 | 有效分母 |
|---|---|---|
| top-1 命中 | **37/42 = 88.1%** | 只算有具名金标的 42 条（每条粒度 2.38pt） |
| Recall@1 / @2 / @3 | 88.1% / 90.5% / **100.0%** | 同上 |
| 人工判空 3 条的 top-1 分数 | 0.575(2014) / 0.564(2012) / 0.607(2005) | 不参与准确率，只给分布 |

错例 5 条（含次优分数，看是不是"第二个服务也说得通"）：

| case | gold | pred | pred 分数 | gold 分数 |
|---|---|---|---|---|
| dp-v2-017 | 2007 | 2003 | 0.587 | 0.585 |
| dp-v2-022 | 2009 | 2011 | 0.634 | 0.589 |
| dp-v2-038 | 2007 | 2003 | 0.644 | 0.540 |
| dp-v2-041 | 2005 | 2010 | 0.538 | 0.471 |
| dp-v2-045 | 2009 | 2001 | 0.598 | 0.551 |

- dp-v2-017 的 gold/pred 只差 0.002 —— 这条按任何阈值都是掷硬币。
- 5 条错例里有 2 条（017、045）正是 P1 里被点名为"Go 侧已过期"的 4 条中的两条，
  另外 023 也在过期名单上、且它对拼接方式敏感（见 `docs/P0_PROBES.md` 的更正小节）。
  **重标这 4 条不是形式主义**：dense 与旧人工金标分歧的位置，和 Go 侧判定过期的位置重合。
- Recall@3 = 100% 说明层 1 把正确答案一律留在了 top-3 里，层 2 的输入不需要更大候选集。

**阈值为什么买不回被删的门**（`t` 同时决定"多少具名工单被误判成无服务"）：

| t | 被闸拦掉的具名工单 | 其中 top-1 本来就对（= 净赔） | 判空 3 条漏网 |
|---|---|---|---|
| 0.55 | 2 | 1（−2.4pt） | 3 |
| 0.575 | 3 | 2（−4.8pt） | 2 |
| 0.607 | 9 | 6（−14.3pt） | 1 |
| **0.62（挡住全部判空）** | 10 | **7（−16.7pt）** | 0 |

具名金标 top-1 分数分位：min 0.485 / p10 0.585 / p25 0.622 / p50 0.651 / max 0.785。
判空三例（0.564–0.607）落在具名命中的 p10–p25 之间 —— **区间重叠，单阈值不可分**。
所以判空继续按 P0 的结论走：层 1 只报分数，`无服务可归` 由层 2 枚举里的 `ESCALATE_HUMAN` 落。

## 数字 ②：检索轴（`retrieval.json`：32 chunks / 15 docs / 90 queries，其中 10 条不可回答）

| 指标 | dense（bge-m3, COSINE） |
|---|---|
| Recall@1 / @3 / @5 | **85.0% / 93.8% / 96.2%** |
| MRR | 0.899 |
| 不可回答查询 top-1 分数 | min 0.423 / p50 0.470 / **max 0.544** |

指标在**文档级**算（chunk 命中折成 doc，同文档保留最高分、按首次出现定序），
分母是 80 条可回答查询；10 条不可回答只用于定阈值。

阈值扫描（pass = 可回答首命中过闸比例，leak = 不可回答被放过比例）：

| t | pass | leak |
|---|---|---|
| 0.45 | 1.000 | 0.600 |
| 0.50 | 1.000 | 0.300 |
| **0.55** | **0.938** | **0.000** |
| 0.60 | 0.863 | 0.000 |
| 0.70 | 0.200 | 0.000 |

→ 取 `KNOWLEDGE_SCORE_THRESHOLD = 0.55`：不可回答零放过，代价是 6.2% 的可回答查询被闸拦掉
（这些是首命中分数落在 0.50–0.55 的弱命中，`score_threshold` 只在知识注入这条路生效）。
这个数不是拍的，是上面这张表选的；改它必须重跑 `make eval-retrieval`。

## 与 Go 的对照（同规则重算后）

Go 的 BM25+置信门在同一份人工金标上：42/45 = 93.3%。
dense 按 Go 自己的判分规则（阈值只对 `gold=0` 生效、具名只看 id）：40/45 = 88.9%（最优 t=0.61）。
**净赔 2 条 / 4.4pt。** 我在 P0 文档里一度写成"净赔 5 条 / 11.1pt"，那是把阈值同时套在具名案例上
算出来的口径错误，已在 `docs/P0_PROBES.md` 就地更正。

## 已知限制

- 45 条 ⟹ 每条 2.38pt，低于本仓库「金标 <100 条不当结论」门槛；以上都是方向性证据。
- 检索阈值是在这份 32-chunk 语料上定的，换语料（尤其加英文或短标题）必须重扫。
- 层 2 指派轴还没跑：它要真模型（`qwen3:8b`）+ P1 的人工指派金标，属于 P4；
  届时必须报"同输入 N 次跑的翻转率 + 均值"，`metrics.flip_rate` 已经备好并被单测覆盖。
- 去重闸用字元覆盖率双向取小（`min(cov(a,b), cov(b,a)) ≥ 0.70`），只防"同一问题重复上报"，
  不防"同一服务不同故障"，后者交给层 1 的服务命中 + 人工判断。
